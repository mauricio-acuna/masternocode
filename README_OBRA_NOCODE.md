# Guia de arranque editorial - Obra Code / No-Code

Este paquete prepara el material de `suplemento` para trabajarlo como una obra literaria tecnica independiente de Spotybank.

## Decision editorial principal

El material debe tratarse como una obra distinta, no como capitulo directo de Spotybank.

Motivo:

- El dominio es e-commerce, integraciones, agentes de IA, vendors, ETL, n8n y operacion propia.
- Spotybank es una obra de modernizacion de microservicios bancarios con identidad ficticia y saneada.
- El suplemento contiene marcas, nombres, contactos y datos de un caso/charla que deben revisarse antes de publicar.

## Titulo de trabajo

```text
Code / No-Code: IA, cajas negras y el nuevo oficio del developer
```

## Subtitulo de trabajo

```text
Como construir sistemas transparentes, observables y baratos de operar cuando la IA cambia la forma de resolver problemas
```

## Proposito

Convertir una charla tecnica de 16 diapositivas en una obra breve, publicable y reutilizable sobre:

- La falsa dicotomia entre code y no-code.
- El problema de las cajas negras.
- El costo real de vendors opacos.
- El uso de knowledge bases como base para agentes de IA.
- Observabilidad como feature.
- Operacion propia y reduccion de dependencia.
- El nuevo rol del developer como disenador de preguntas, contexto y sistemas operables.

## Material base disponible

- `code_no_code_markdown_limpio.md`: extraccion curada con analisis por diapositiva.
- `code_no_code_texto_literal_slides.md`: transcripcion literal de las 16 diapositivas.
- `code_no_code_plan_editorial_accionable.md`: plan de contenidos, posts, articulos, newsletter, lead magnet y charla.
- `programa_contenidos_code_no_code*.docx`: versiones DOCX del programa.
- `1.png` a `16.png`: imagenes fuente de las diapositivas.

## Como usar este paquete con otra IA

1. Abrir primero `00_GESTION_PROYECTO/INSTRUCCIONES_PARA_OTRA_IA.md`.
2. Leer `01_MATERIAL_BASE/MAPA_MATERIAL_EXISTENTE.md`.
3. Confirmar si la obra se publicara con marcas/personas reales o con caso anonimizado.
4. Usar `02_PLANIFICACION/INDICE_PROVISIONAL_NOCODE.md` como estructura inicial.
5. Redactar capitulos siguiendo `02_PLANIFICACION/METODO_TRABAJO_IA.md`.
6. Antes de publicar, ejecutar `09_REVISIONES/CHECKLIST_REVISION_TECNICA_EDITORIAL_NOCODE.md`.

## Regla de oro

No convertir frases de la charla en afirmaciones universales. El caso puede ser potente, pero debe presentarse como caso especifico, patron replicable o hipotesis de trabajo segun corresponda.
