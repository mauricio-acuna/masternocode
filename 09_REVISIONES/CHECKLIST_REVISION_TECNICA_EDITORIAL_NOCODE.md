# Checklist de revision tecnica y editorial

## Identidad y permisos

- [ ] Se decidio si se publican nombres reales o caso anonimizado.
- [ ] Los datos de contacto fueron removidos o autorizados.
- [ ] Las marcas comerciales se usan con criterio editorial.
- [ ] Las imagenes/slides tienen permiso de uso o se reemplazan.
- [ ] No hay datos privados del cliente.

## Revision tecnica

- [ ] El texto diferencia ETL, no-code, low-code, agentes e integraciones custom.
- [ ] No afirma que n8n falle siempre.
- [ ] No afirma que agentes sean siempre mejores.
- [ ] Los numeros del caso se presentan como resultados especificos.
- [ ] Observabilidad, logs y metricas se explican como criterios de operacion.
- [ ] Knowledge base aparece como requisito previo, no como adorno.
- [ ] Costos se tratan con contexto.

## Revision editorial

- [ ] La tesis central es clara.
- [ ] La narrativa sigue problema, intentos, aprendizaje y alternativa.
- [ ] Cada capitulo tiene una idea principal.
- [ ] Hay tablas, checklists o preguntas aplicables.
- [ ] El tono no es anti-vendor ni anti-no-code por principio.
- [ ] No hay humo generico de IA.

## Revision comercial

- [ ] La obra identifica audiencia y uso.
- [ ] Hay una propuesta de valor concreta.
- [ ] El lead magnet o piezas derivadas no prometen de mas.
- [ ] Las oportunidades de negocio se plantean como discovery, no como garantia.

## Criterio de salida

La obra puede pasar a borrador publicable cuando:

- El tratamiento de marcas/personas este decidido.
- La estructura de capitulos este completa.
- Los claims del caso esten contextualizados.
- Las piezas promocionales no exageren resultados.
- Exista licencia o criterio de uso.
